# Primitive DB

Учебная консольная база данных на Python 3.12.

Проект реализован в процедурном стиле.

## Технологии

- Python 3.12+
- uv
- Git
- Ruff
- prompt
- PrettyTable
- JSON
- unittest

## Установка

Клонирование репозитория:
```bash
git clone https://github.com/dariakuznetsova23-max/-project-2_kuznetsovads_M26-555.git primitive-db
cd primitive-db
uv sync
```

## Запуск
```bash
uv run database
```

Альтернативные варианты:
```bash
uv run project
uv run python -m primitive_db.main
```

## Управление таблицами

Создание таблицы:
```text
create_table users name:str age:int is_active:bool
```

Поддерживаемые типы:

- int — целое число;
- str — строка;
- bool — true или false.

Столбец ID:int добавляется автоматически.

Если ID указан явно в описании таблицы, допустима только запись ID:int.
Значения ID при вставке записей передавать нельзя.

Имена таблиц и столбцов состоят из латинских букв, цифр и
подчёркивания. Имя не может начинаться с цифры.
Имена таблиц и столбцов чувствительны к регистру.

Список таблиц:
```text
list_tables
```

Информация о таблице:
```text
info users
```

Удаление таблицы:
```text
drop_table users
```

Перед удалением программа запрашивает подтверждение.
Операция выполняется только при ответе y.

## CRUD-операции

### Добавление
```text
insert into users values ("Sergei", 28, true)
insert into users values ("Анна, Мария", 23, false)
```

Все пользовательские поля обязательны.

Строки нужно заключать в одинарные или двойные кавычки.
Целые числа и true/false вводятся без кавычек.

ID генерируется автоматически как максимальный существующий ID + 1.
После удаления записей ранее использованный ID может быть выдан снова.

### Чтение

Все записи:
```text
select from users
```

Записи по условию:
```text
select from users where age = 28
select from users where ID = 1
```

Результат выводится с помощью PrettyTable.

### Обновление
```text
update users set age = 29 where name = "Sergei"
```

Несколько полей:
```text
update users set name = "Сергей", age = 30 where ID = 1
```

Изменять ID нельзя.

### Удаление
```text
delete from users where ID = 1
```

Перед удалением программа запрашивает подтверждение.

Для update и delete условие where обязательно.
Поддерживается одно условие равенства.
AND, OR и другие операторы сравнения не реализованы.

## Хранение данных

Метаданные таблиц сохраняются в db_meta.json.

Данные каждой таблицы сохраняются в отдельном файле:
```text
data/users.json
```

Файлы базы создаются относительно текущей рабочей директории.
Поэтому для работы с одной и той же базой запускайте программу
из одной и той же директории.

Локальные файлы базы не добавляются в Git.

При отсутствии JSON-файла загрузчик возвращает пустую структуру.
Ошибки чтения и некорректный JSON выводятся пользователю.

Перед заменой JSON-файла данные записываются во временный файл.
Межфайловые транзакции и одновременная работа нескольких процессов
не поддерживаются.

## Декораторы

handle_db_errors централизованно обрабатывает ошибки.

confirm_action запрашивает подтверждение удаления таблиц и записей.

log_time измеряет время выполнения insert и select
с помощью time.monotonic().

## Кэширование

create_cacher возвращает функцию с кэшем в замыкании.

Результаты одинаковых select-запросов кэшируются.
Ключ включает содержимое данных и условие запроса,
поэтому изменённые данные не используют устаревший результат.

Возвращаются копии результатов, защищающие кэш от изменения.
Размер кэша ограничен 128 ключами с очисткой при переполнении.

Это учебная реализация: сериализация данных для построения ключа
сама требует времени и не предназначена для больших таблиц.
